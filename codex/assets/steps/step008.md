# Step 8 - jscpd 코드 중복 탐지 환경 설치

## 목표

jscpd CLI의 가용성을 확인하고, 사용할 수 있으면 검증된 버전을 기록한다. 이 기능은
선택 사항이므로 제한된 설치 시도가 실패해도 완료를 가장하지 않고 명시적인 대체
경로를 남긴다.

## 입력과 산출물

- 입력: `package.json`
- 입력: `step_archive/step001_preflight.md`
- 필수 선행 항목: `step001`
- 산출물: `step_archive/step008_jscpd_test.md`
- 네트워크: 패키지 설치가 필요할 때 사용할 수 있다.
- 시각 검토: 필요하지 않다.
- 기능 분류: 선택

## 실행 역할

가능한 경우 현재 단계 범위의 jscpd 설치 시도·버전 확인 또는 SKIP 근거 수집만 독립적인 도구 준비 작업자 역할에 위임한다.
작업자는 제한된 명령과 대체 방법의 근거만 보고한다.
검증자 역할은 작업자 결과를 그대로 수락하지 않고 성공한 버전 명령 또는 이유 있는 `SKIP`, 종료 코드와 보고서를 확인한다.
역할을 나눠도 정상 권한 확인은 그대로 유지한다.
위임 기능을 사용할 수 없으면 현재 실행자가 두 역할을 순서대로 수행하고, 별도 작업자를 사용했다고 기록하지 않는다.

## 설치와 검증

프로젝트 루트에서 다음 버전 명령을 먼저 실행한다.

```text
npx jscpd --version
```

사용할 수 없고 프로젝트가 npm을 사용하면 정상 권한 확인 아래 다음 명령을 실행할
수 있다.

```text
npm install --save-dev jscpd
```

설치와 버전 확인을 합쳐 최대 세 번까지만 시도한다.
버전 또는 smoke 명령이 종료 코드 0으로 성공한 경우에만 도구를 `설치됨`으로 기록한다.
패키지 이름이나 디렉터리 존재만으로 성공을 주장하지 않는다.

jscpd를 사용할 수 없으면 `SKIP`으로 기록하고 이유와 안전한 대체 방법으로 관련
파일을 좁혀 구조적 검색과 수동 중복 검토를 수행하도록 명시한다. 이 `SKIP` 기록을
수락 증거로 제출할 수 있지만, jscpd 실행 성공을 주장해서는 안 된다.

## 환경 보고서

`step_archive/step008_jscpd_test.md`에 다음 내용을 기록한다.

- 버전 명령, 종료 코드, 확인된 버전 또는 `SKIP`
- 설치를 시도했다면 명령과 시도 횟수
- `SKIP`이면 비밀값이 제거된 오류 범주, 이유와 대체 방법

## 완료 조건

- `jscpd-version`: 사용할 수 있을 때 버전 명령이 종료 코드 0으로 끝난다.
- `jscpd-environment-report`: 환경 보고서가 존재한다.
- `jscpd-disposition`: 검증된 버전이 있는 `OK` 또는 이유와 대체 방법이 있는
  `SKIP`이 기록된다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

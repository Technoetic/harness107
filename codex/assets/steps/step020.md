# Step 20 - Awwwards 사이트 선정

## 목표

16단계의 프로젝트 특성을 근거로 Awwwards에 실제 등재된 참고 사이트를 소수
선정하고, 각 선정 URL과 등재 출처를 이후 수집이 재현할 수 있게 기록한다.

## 입력과 산출물

- 입력: `step_archive/TOPIC/TOPIC.md`
- 입력: `step_archive/step016_조사결과_chunk1.md`
- 필수 선행 항목: `step016`
- 산출물: `step_archive/step020_선정URL.md`
- 산출물: `step_archive/research-raw-step020-awwwards.txt`
- 네트워크: 필수
- 시각 검토: 필요하지 않다.

## 실행 역할

가능한 경우 특성별 후보 수집 역할과 등재·관련성을 원본에 대조하는 독립 검토 역할을
나눈다. 수집 역할은 실제 후보 URL과 등재 출처를 모으고, 독립 검토 역할은 후보가
주제 특성을 뒷받침하는지 확인한다. 역할을 나눠도 정상 권한 확인은 유지한다.
위임 기능을 사용할 수 없으면 현재 실행자가 수집과 독립 검토를 순서대로 수행한다.
별도 역할을 위임했다고 기록하지 않는다.

## 선정 절차

주제 입력과 16단계 조사 청크에서 프로젝트 유형, 핵심 기능, 대상 사용자, UI 구성
요소를 추출한다. 각 특성에 대응하는 질문을 만든 뒤 지원되는 웹 또는 브라우저 수집
기능으로 Awwwards 등재 페이지와 실제 사이트를 방문한다. 사전에 특정 카테고리나
미학을 고정하지 않는다.

선정에 사용한 첫 Awwwards 등재 페이지의 실제 원본 텍스트를
`step_archive/research-raw-step020-awwwards.txt`에 보존한다. 다른 후보의 동적 원본
또는 캡처를 만들면 선정 문서의 출처 표에 그 경로를 빠짐없이 기록한다. 원본 파일을
만들 수 없는 페이지의 사실은 선정 근거로 사용하지 않는다.

관련성과 이후 수집 비용을 함께 고려해 최대 3개 사이트만 선정한다. 각 항목에는
다음을 기록한다.

- Awwwards 등재 URL과 실제 사이트 URL
- 선정 이유와 연결되는 16단계 근거 위치
- 확인한 페이지 제목, HTTP 결과와 수집 시각
- 반응형 여부에 대한 현재 근거와 조사할 viewport
- 등재 페이지 원본 또는 캡처 경로

모든 사실 주장은 URL과 출처, 원본 또는 캡처 위치로 추적되어야 한다. 실제 등재를
확인하지 않은 후보나 접근하지 않은 화면의 증거를 발명하지 않는다.

네트워크 기능을 사용할 수 없으면 원인을 기록한다. 실제 등재와 사이트 URL을
확인하지 못한 경우와 함께 정상 권한 확인 아래 최대 세 번만 재시도한다. 그래도 최소 한 개의 근거 있는 사이트를
선정하지 못하면 원인과 사용자 조치를 기록하고 이 단계를 완료하지 않는다.

## 결과 형식

`step_archive/step020_선정URL.md`에 선정 기준, 동적 질문, 최대 3개의 번호 있는 항목,
출처 표와 `step_archive/research-raw-step020-awwwards.txt`의 연결을 기록한다. 다른
workflow 기록이나 과거 실패 목록을 읽어 선정 결과를 추측하지 않는다.

## 완료 조건

- `selected-awwwards-urls`: 선정 URL 문서가 존재한다.
- `awwwards-listing-raw`: 실제 Awwwards 등재 페이지의 primary 원본 텍스트가 존재한다.
- `evidence-derived-selection`: 모든 후보가 주제 특성과 16단계 근거에서 도출되었다.
- `selected-url-attribution`: 등재 URL, 실제 URL, 수집 시각과 원본 위치가 기록된다.
- `bounded-site-set`: 관련성이 검증된 사이트가 최대 3개만 선정되었다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

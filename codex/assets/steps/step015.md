# Step 15 - madge 순환 의존성 탐지 환경 설치

## 목표

madge CLI의 가용성을 확인하고, 사용할 수 있으면 검증된 버전을 기록한다. 사용할 수
없을 때는 선택 기능을 건너뛴 사실과 의존성 검토의 대체 방법을 명시한다.

## 입력과 산출물

- 입력: `package.json`
- 입력: `step_archive/step001_preflight.md`
- 필수 선행 항목: `step001`
- 산출물: `step_archive/step015_madge_test.md`
- 네트워크: 패키지 설치가 필요할 때 사용할 수 있다.
- 시각 검토: 필요하지 않다.
- 기능 분류: 선택

## 설치와 검증

프로젝트 루트에서 다음 버전 명령을 먼저 실행한다.

```text
npx madge --version
```

사용할 수 없고 프로젝트가 npm을 사용하면 정상 권한 확인 아래 다음 명령을 실행할
수 있다.

```text
npm install --save-dev madge
```

설치와 버전 확인을 합쳐 최대 세 번까지만 시도한다.
버전 또는 smoke 명령이 종료 코드 0으로 성공한 경우에만 도구를 `설치됨`으로 기록한다.
패키지 이름이나 디렉터리 존재만으로 성공을 주장하지 않는다.

madge를 사용할 수 없으면 `SKIP`으로 기록하고 이유와 안전한 대체 방법으로 빌드
도구가 제공하는 의존성 그래프와 범위 제한 import 검토를 사용하도록 명시한다. 이
`SKIP` 기록을 수락 증거로 제출할 수 있지만 순환 의존성 검사를 실행했다고 주장하지
않는다.

## 이후 소스 주석 계약

이 시점 이후 새 소스 파일에는 언어가 주석을 지원하고 프로젝트 규칙과 충돌하지
않는 범위에서 다음 주석 체계를 적용한다.

```text
@MX:NOTE: 중요한 맥락이나 의도
@MX:WARN: 위험 영역, 함께 적는 @MX:REASON 포함
@MX:ANCHOR: 여러 소비자가 의존하는 불변 계약, 함께 적는 @MX:REASON 포함
@MX:TODO: 아직 끝나지 않은 작업
```

새 구현 파일에는 관련 맥락을 설명하는 `@MX:NOTE`를 최소 하나 둔다. 의미 없는
주석을 수량 충족용으로 만들지 않으며, 이 주석 계약은 실행 검증을 대신하지 않는다.

## 환경 보고서

`step_archive/step015_madge_test.md`에 다음 내용을 기록한다.

- 버전 명령, 종료 코드, 확인된 버전 또는 `SKIP`
- 설치를 시도했다면 명령과 횟수
- `SKIP`이면 비밀값이 제거된 오류 범주, 이유와 대체 방법
- 이후 소스 주석 계약을 적용할 때의 프로젝트별 제약

## 완료 조건

- `madge-version`: 사용할 수 있을 때 버전 명령이 종료 코드 0으로 끝난다.
- `madge-environment-report`: 환경 보고서가 존재한다.
- `madge-disposition`: 검증된 버전이 있는 `OK` 또는 이유와 대체 방법이 있는
  `SKIP`이 기록된다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

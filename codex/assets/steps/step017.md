# Step 17 - GitHub 조사

## 목표

주제와 관련된 공개 저장소를 GitHub API로 실제 조사하고, 재현 가능한 요청·응답
증거와 이후 코드 분석에 사용할 후보를 남긴다. 신규 프로젝트라는 이유로 건너뛰거나
응답을 추측하지 않는다.

## 입력과 산출물

- 입력: `step_archive/TOPIC/TOPIC.md`
- 입력: `step_archive/step016_조사결과_chunk1.md`
- 필수 선행 항목: `step016`
- 산출물: `step_archive/step017_조사결과_chunk1.md`
- 산출물: `step_archive/research-raw-step017-github-api.json`
- 네트워크: 필수
- 시각 검토: 필요하지 않다.

## 실행 역할

가능한 경우 우선순위 검색어를 한 번에 하나씩 처리하는 단일 API 수집 역할과 후보
품질을 응답 원본으로 확인하는 독립 검토 역할을 나눈다. API 수집 역할은 실제 요청과
원본 보존만 담당하고 병렬 fan-out을 하지 않는다. 독립 검토 역할은
관련성·라이선스·활동 정보가 보존된 응답과 일치하는지 확인한다. 역할을 나눠도 정상
권한 확인은 유지한다. 위임 기능을 사용할 수 없으면 현재 실행자가 수집과 독립 검토를
순서대로 수행하고, 별도 역할을 위임했다고 기록하지 않는다.

## 조사 절차

주제 입력과 16단계 결과에서 최대 세 개의 구체적인 검색어 후보를 만들고 API 요청 전
우선순위를 정한다. 후보를 URL 인코딩한 뒤
`https://api.github.com/search/repositories`의 공개 검색 API에 한 번에 하나씩
요청한다. 각 후보당 최대 한 번, 총 최대 세 번의 실제 요청만 허용하며 병렬 요청은
하지 않는다.

첫 HTTP 성공 응답의 수정하지 않은 JSON 바이트를
`step_archive/research-raw-step017-github-api.json`에 저장한다. 저장하는 즉시 추가 API
요청과 검색어·저장소 후보 수집을 중단한다. 성공 응답은 정확히 하나만 보존하고 기존
원본을 덮어쓰거나 다른 응답을 합치지 않는다. 관련성이 높은 저장소 후보는 오직 이
보존된 성공 응답 안에서 최대 스무 개까지만 비교한다. 후보 선정과 모든 사실 주장은
오직 해당 보존된 성공 응답의 필드로 제한한다. 청크에는 다음을 포함한다.

- 요청 URL, 응답 시각, HTTP 상태, rate-limit 관련 공개 헤더
- 원본 JSON 경로와 검색어
- 후보의 저장소 URL, 설명, 주요 언어, 라이선스, 최근 갱신 시각
- 주제와의 관련성 및 19단계에서 정적 분석할 우선순위

실패 시도는 시도 번호, 요청 URL, 응답 시각, HTTP 상태와 rate-limit 공개 metadata만
청크 manifest에 기록한다. 실패 응답 본문은 후보 근거로 보존하지 않으며, 실패
응답에서 나온 사실이나 후보를 사용하지 않는다.

인증 값이나 환경 변수는 저장하지 않는다. 모든 사실 주장은 요청 URL과 출처,
원본 JSON의 필드 위치로 추적되어야 한다. 응답에 없는 별·라이선스·활동 정보를
채워 넣거나 후보를 찾은 것처럼 증거를 발명하지 않는다.

네트워크 기능을 사용할 수 없으면 비밀값을 제외한 원인만 기록한다. 기능은 있지만
성공 응답이 없으면 정상 권한 확인 아래 우선순위 후보를 한 번씩 최대 세 번까지
시도한다. 그 뒤에도 실제 성공 응답 원본이 없으면 이 단계를 완료하지 않는다.

## 청크 계약

첫 결과는 `step_archive/step017_조사결과_chunk1.md`에 저장한다. 추가 청크가 필요하면
각각 500줄 이하로 만들고 첫 청크 manifest에 정확한 경로와 줄 수를 기록한다. 원본
JSON을 요약문으로 대체하지 않는다.

## 완료 조건

- `github-research-chunk-1`: 첫 조사 청크와 청크 manifest가 존재한다.
- `github-api-raw`: 실제 성공 응답의 수정하지 않은 JSON이 존재한다.
- `github-api-response`: 요청 URL, 응답 시각, HTTP 성공 상태가 원본과 일치한다.
- `github-attribution`: 각 후보와 판단이 원본 필드 및 저장소 URL로 추적된다.
- `github-chunks-bounded`: manifest의 모든 청크가 존재하며 500줄 이하이다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

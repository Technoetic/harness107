# Step 19 - 참고 레포지토리 클론 및 코드 분석

## 목표

17단계에서 보존한 단일 성공 API 응답에서 선별한 공개 저장소를 격리된 참고 경로에
얕게 복제하고, 코드를 실행하지 않은 채 구조와 설계 패턴을 정적으로 분석한다.

## 입력과 산출물

- 입력: `step_archive/step017_조사결과_chunk1.md`
- 입력: `step_archive/research-raw-step017-github-api.json`
- 필수 선행 항목: `step017`
- 산출물: `step_archive/step019_조사결과_chunk1.md`
- 산출물: `step_archive/references/clone-manifest.md`
- 네트워크: 필수
- 시각 검토: 필요하지 않다.

## 실행 역할

가능한 경우 저장소별 수집 역할과 정적 분석을 원본 파일에 대조하는 독립 검토 역할을
나눈다. 수집 역할은 검증된 경로에 얕은 복제만 수행하고, 독립 검토 역할은 manifest,
commit, 분석 근거가 일치하는지 확인한다. 역할을 나눠도 정상 권한 확인은 유지한다.
위임 기능을 사용할 수 없으면 현재 실행자가 수집과 독립 검토를 순서대로 수행하고,
별도 역할을 위임했다고 기록하지 않는다.

## 후보와 경로 검증

오직 `step_archive/research-raw-step017-github-api.json`에 보존된 단일 성공 응답에
실제로 존재하고 조사 청크가 관련성을 설명한 후보만 복제 대상으로 선택한다. 최대
5개만 허용한다. 17단계 manifest의 실패 시도 metadata와 보존되지 않은 응답은 출처가
아니다. 그 후보나 클론 URL은 사용하지 않는다. URL은
`https://github.com/<owner>/<repo>` 형식의 공개 저장소만 허용한다. owner와 repo
이름에서 영문 소문자, 숫자, 점, 밑줄, 하이픈 외 문자를 제거하는 대신 유효하지 않은
후보를 거부한다.

각 대상은 정규화하고 해석한 뒤 검증된 `step_archive/references/owner-repo` 같은
단일 하위 경로에만 둔다. 대상 또는
부모가 심볼릭 링크, junction 등으로 작업 경계 밖을 가리키면 복제하지 않고 이
단계를 완료하지 않는다. 기존 디렉터리는 자동 덮어쓰지 않고 출처와 commit이 정확히
일치할 때만 읽기 전용 참고 대상으로 재사용한다.

## 얕은 복제와 격리

복제는 반드시 `git clone --depth 1` 형태로 시작하며 각 후보에 다음 명령만 사용한다.

```text
git clone --depth 1 -- <검증된-URL> <검증된-대상-경로>
```

클론한 코드는 신뢰하지 않는다. 패키지 설치, 빌드, 테스트, 프로젝트 스크립트,
실행 파일, 자동화 구성은 실행 금지다. 하위 저장소나 대용량 파일 확장도 자동으로
가져오지 않는다. 일반 텍스트 소스와 설정을 정적으로 조사할 뿐이다.

성공한 각 복제의 URL, 최종 commit, 대상 경로, 수집 시각을 manifest에 기록한다.
실패한 후보도 URL, 시도 횟수, 비밀값이 제거된 오류 범주를 manifest에 기록하고 다른
후보를 계속 처리한다. 최소 한 개의 관련 저장소를 실제 복제하지 못하면 완료하지
않는다.

네트워크 기능을 사용할 수 없으면 정상 권한 확인 아래 최대 세 번만 재시도한다.
그 뒤에도 관련 저장소를 실제 복제하지 못하면 이 단계를 완료하지 않는다. 요청 URL,
출처 API 원본, 응답 시각과 복제 결과를 보존한다. 모든 사실 주장은 URL과
출처, 원본 또는 복제된 파일 경로와 줄 범위로 추적되어야 하며 증거를 발명하지 않는다.

## 정적 분석 범위

저장소마다 다음 항목만 분석한다.

- 디렉터리 구조와 기술 스택
- package manifest, compiler 및 build 설정의 선언
- 주요 진입점, routing, component와 module 경계
- 상태 관리와 데이터 흐름 패턴
- 현재 프로젝트에 적용 가능한 점과 적용하지 말아야 할 제약

첫 결과는 `step_archive/step019_조사결과_chunk1.md`에 저장한다. 추가 청크는 각각
500줄 이하로 만들고 첫 청크 manifest에 정확한 경로와 줄 수를 기록한다.

## 완료 조건

- `repository-analysis-chunk-1`: 첫 정적 분석 청크가 존재한다.
- `clone-manifest`: 최대 5개 후보의 성공과 실패, URL, commit, 경로가 기록된다.
- `bounded-shallow-clones`: 모든 새 복제가 검증된 경로와 `--depth 1`을 사용했다.
- `cloned-code-quarantine`: 복제된 코드의 설치·빌드·스크립트·실행이 없었다.
- `repository-analysis-chunks-bounded`: manifest의 모든 청크가 존재하며 500줄 이하이다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

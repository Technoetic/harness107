# Step 26 - 기획 보강: GitHub 조사결과

## 목표

25단계 기초 기획에 17단계의 보존된 단일 성공 API 응답에서 확인되는 공개 저장소
사실과 패턴을 더한 별도 기획 스냅샷을 만든다. 기존 스냅샷을 덮어쓰지 않으며 새 API 요청을 금지한다.

## 입력과 산출물

- 입력: `step_archive/step025_planning_chunk1.md`
- 입력: `step_archive/outputs/step025_검증.md`
- 입력: `step_archive/step017_조사결과_chunk1.md`
- 입력: `step_archive/research-raw-step017-github-api.json`
- 필수 선행 항목: `step017`, `step025`
- 산출물: `step_archive/step026_planning_chunk1.md`
- 산출물: `step_archive/outputs/step026_검증.md`
- 네트워크: 사용하지 않는다.
- 시각 검토: 필요하지 않다.

## 실행 역할

가능한 경우 GitHub 근거 보강 작성자 역할과 GitHub 근거 독립 검증자 역할을 나눈다.
작성자는 기초 기획을 별도 스냅샷으로 보강하고, 독립 검증자는 작성 산출물을 수정하지
않는다. 검증자는 보존 응답과 결정의 일치를 독립적으로 판정한다. 위임 기능을 사용할
수 없으면 현재 실행자가 두 역할을 명확히 분리해 순서대로 수행하고, 별도 역할을
위임했다고 기록하지 않는다. 정상 권한 확인을 유지하고 자동 승인이나 권한 우회를
금지한다.

## 보존 응답 경계

두 17단계 입력을 실제로 읽고, 보존된 단일 성공 API 응답에 존재하는 후보와 사실만
사용한다. 조사 manifest의 실패 시도나 보존되지 않은 응답은 근거가 아니다. 새 API 요청,
웹 탐색과 저장소 복제는 금지한다. 필수 입력이 없거나 25단계 검증 최종 판정이
`PASS`가 아니면 이 단계를 완료하지 않는다.

## 별도 보강 스냅샷

`step_archive/step026_planning_chunk1.md`에 25단계 내용을 그대로 복사하는 대신 변경
기준과 보강 결과를 완전한 기획 스냅샷으로 작성한다. 기능 범위, Class 책임, 모듈
경계, 데이터 흐름, 적용할 패턴과 적용하지 않을 패턴을 모두 포함한다. 각 아키텍처와
패턴 결정에는 출처 경로, 성공 응답 항목, 저장소 식별자와 조사 청크 절을 기록한다.
근거가 한 후보에만 있을 때는 일반화하지 않고 불확실성을 남긴다.

첫 청크 manifest에 입력 digest, 25단계 대비 변경 목록, 결정별 provenance와 줄 수를
기록한다. 스냅샷은 500줄 이하이며 다른 기획 파일을 덮어쓰지 않는다. 선언되지 않은
추가 청크가 필요하면 임의 생성하지 않고 차단한다.

## bounded 독립 검증

모든 라운드는 동일한 선언 보고서 `step_archive/outputs/step026_검증.md`에 라운드별 섹션으로
기록한다. 검증자는 후보 존재, 사실 정확성, 결정 provenance, 기초 기획 보존,
과도한 일반화를 확인한다. 최대 5라운드만 수행한다.

- `PASS`: 모든 보강 결정이 보존 응답과 조사 청크에 연결된 경우에만 완료한다.
- `FAIL`: 완료 증거가 될 수 없다. 작성자가 같은 스냅샷을 보정한 뒤 독립 재검증한다.
- 실패 항목을 건너뛰거나 새 자료로 대체하지 않는다.
- 5라운드까지 `PASS`가 없으면 workflow를 차단하고 미해결 근거를 같은 보고서에
  남긴다.

## 완료 조건

- `github-planning-snapshot`: GitHub 증거를 반영한 별도 완전 스냅샷이 있다.
- `github-planning-verification`: 단일 보고서에 모든 검증 라운드가 있다.
- `persisted-github-response-only`: 오직 보존된 성공 응답의 후보와 사실을 사용했다.
- `decision-provenance`: 아키텍처와 패턴 결정이 응답 항목까지 추적된다.
- `planning-chunks-bounded`: manifest와 스냅샷이 일치하며 500줄 이하이다.
- `bounded-independent-review`: 검증은 다섯 번 안에서 독립적으로 수행됐다.
- `pass-verdict`: 최종 판정이 근거 있는 `PASS`다.

검증 결과와 두 산출물의 경로를 수락 증거로 제출하고 현재 단계에서 멈춘다.
workflow 상태와 영수증만이 이후 진행을 소유한다.

# Step 11 - tokei 코드 통계 환경 설치

## 목표

tokei CLI의 가용성을 확인하고, 사용할 수 있으면 검증된 버전을 기록한다. 현재
플랫폼에 적절한 설치 수단이 없을 때는 선택 기능을 건너뛴 사실과 대체 측정 방법을
명시한다.

## 입력과 산출물

- 입력: `step_archive/step001_preflight.md`
- 필수 선행 항목: `step001`
- 산출물: `step_archive/step011_tokei_test.md`
- 네트워크: 패키지 설치가 필요할 때 사용할 수 있다.
- 시각 검토: 필요하지 않다.
- 기능 분류: 선택

## 설치와 검증

다음 명령을 먼저 실행한다.

```text
tokei --version
```

사용할 수 없으면 운영체제와 프로젝트에서 이미 사용하는 신뢰 가능한 패키지 관리
방식을 확인한 뒤 정상 권한 확인 아래 설치할 수 있다. 새로운 시스템 패키지
관리자를 이 단계만을 위해 자동으로 추가하지 않는다. 설치와 버전 확인을 합쳐 최대
세 번까지만 시도한다.

버전 또는 smoke 명령이 종료 코드 0으로 성공한 경우에만 도구를 `설치됨`으로 기록한다.
실행 파일의 추정 경로나 설치 명령의 종료만으로 성공을 주장하지 않는다.

tokei를 사용할 수 없으면 `SKIP`으로 기록하고 이유와 안전한 대체 방법으로 프로젝트
경계 안의 파일 목록 및 언어별 줄 수 집계를 사용하도록 명시한다. 이 `SKIP` 기록을
수락 증거로 제출할 수 있지만 tokei 결과를 발명해서는 안 된다.

## 환경 보고서

`step_archive/step011_tokei_test.md`에 다음 내용을 기록한다.

- 버전 명령, 종료 코드, 확인된 버전 또는 `SKIP`
- 사용한 패키지 관리 방식과 설치 시도 횟수
- `SKIP`이면 비밀값이 제거된 오류 범주, 이유와 대체 방법

## 완료 조건

- `tokei-version`: 사용할 수 있을 때 버전 명령이 종료 코드 0으로 끝난다.
- `tokei-environment-report`: 환경 보고서가 존재한다.
- `tokei-disposition`: 검증된 버전이 있는 `OK` 또는 이유와 대체 방법이 있는
  `SKIP`이 기록된다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

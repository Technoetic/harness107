# Step 24 - Awwwards 조사 충분성 검증

## 목표

23단계 분석이 이후 설계 결정에 충분한지 원본 증거로 독립 검증한다. 실패 항목을
성공으로 바꾸거나 자동 우회하지 않고, `PASS`만 완료로 인정한다.

## 입력과 산출물

- 입력: `step_archive/step016_조사결과_chunk1.md`
- 입력: `step_archive/step022_수집결과_chunk1.md`
- 입력: `step_archive/awwwards-step022-primary.txt`
- 입력: `step_archive/screenshots/research/step022-primary-desktop.png`
- 입력: `step_archive/step023_조사결과_chunk1.md`
- 필수 선행 항목: `step016`, `step022`, `step023`
- 산출물: `step_archive/outputs/step024_검증_r1.md`
- 네트워크: 사용하지 않는다.
- 시각 검토: 필수

## 실행 역할

23단계 분석을 만든 역할과 구분된 독립 검증자 역할이 수집 증거를 처음부터 대조한다.
가능한 경우 별도 검증자에게 맡기고 분석 결론을 그대로 전달하지 않는다.
위임 기능을 사용할 수 없으면 현재 실행자가 수집 자료를 기준으로 독립 검토를
순서대로 수행하며, 별도 역할을 위임했다고 기록하지 않는다. 어느 방식에서도 정상 권한 확인은
유지한다.

## 검증 기준

시각 검사 기능으로 manifest의 필수 스크린샷을 실제로 열어 다음을 평가한다.

- 데이터 기반: 각 결론이 URL, 원본 텍스트와 화면 영역에 연결되는가
- 누락: 프로젝트 특성상 필요한 디자인 요소가 빠지지 않았는가
- 대안 충분성: 각 동적 조사 축에 비교 가능한 근거 있는 대안이 있는가
- 설계 가능성: 장단점과 물리적 제약으로 설계 결정을 내릴 수 있는가
- 추적성: 16·22·23단계의 manifest 경로와 22단계 primary 원본이 서로 일치하는가

시각 검사 기능을 사용할 수 없으면 이 단계를 완료하지 않는다. 필수 스크린샷을
실제로 열어 검사할 수 없는 경우도 같다. 사실 주장과 판정은 URL, 출처, 원본 또는 캡처로
추적되어야 하며 누락된 증거를 발명하지 않는다.

## 판정과 bounded 반복

모든 라운드는 동일한 선언 산출물 `step_archive/outputs/step024_검증_r1.md`의
라운드별 섹션에 저장한다. 라운드 1부터 라운드 5까지 필요한 섹션만 순서대로
추가하며 별도 라운드 파일은 만들지 않는다. 파일 앞의 manifest에는 실제 라운드 수,
검증자 방식, 근거 목록, 항목별 `PASS` 또는 `FAIL`, 최종 판정을 기록한다.
최대 5라운드까지만 허용한다.

- `PASS`: 모든 필수 기준이 근거로 충족된 경우에만 이 단계를 완료한다.
- `FAIL`: 완료 증거가 될 수 없다. 부족 유형, 근거와 권장 보완 범위를 기록한다.
- `FAIL` 보고서는 자동으로 다른 단계로 이동하거나 다른 작업을 실행하지 않는다.
- 5라운드 뒤에도 `PASS`가 없으면 남은 실패를 건너뛰지 않고 현재 workflow를
  차단하며 필요한 사용자 조치를 기록한다.

실패 유형은 사이트 다양성, 페이지·viewport 자료, 분석 깊이 중 하나 이상으로
분류할 수 있다. 이는 진단 정보일 뿐 자동 실행 지시가 아니다. 실패 이력을 다른
플랫폼의 제어 파일에 쓰지 않는다.

## 완료 조건

- `sufficiency-verification-round-1`: 선언된 단일 보고서와 전체 라운드 manifest가 존재한다.
- `verification-screenshot-input`: 필수 primary 스크린샷이 존재한다.
- `independent-verifier`: 분석자와 구분된 독립 검증 절차와 실제 방식을 기록했다.
- `bounded-verification-rounds`: 라운드가 최대 5개이며 누락된 번호가 없다.
- `pass-verdict`: 최종 판정이 근거 있는 `PASS`다.
- `visual-sufficiency-inspection`: 필수 이미지를 실제로 열어 충분성을 검사했다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

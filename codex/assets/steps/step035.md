# Step 35 - 컨텍스트 윈도우 제한 방지

## 목표

구현 중 필요한 근거를 잃지 않으면서 읽기와 작업 범위를 제한하는 구체적 정책을 만든다.
숨겨진 실행 환경이나 관찰할 수 없는 잔량을 근거로 완료를 주장하지 않는다.

## 입력과 산출물

- 입력: `step_archive/step032_파일인덱스_chunk1.md`
- 필수 선행 항목: `step032`
- 산출물: `step_archive/step035_컨텍스트정책.md`
- 네트워크: 사용하지 않는다.
- 시각 검토: 필요하지 않다.

## 실행 역할

이 단계에서는 외부 역할에 위임하지 않는다. 현재 실행자가 정책 수립 패스와 분리된
검증 패스를 순서대로 수행한다. 검증 패스는 정책 산출물을 수정하지 않는다. 별도 역할을
위임했다고 기록하지 않는다. 정상 권한 확인을 유지하고 자동 승인이나 권한 우회를
금지한다.

## 컨텍스트 정책

파일 인덱스를 기준으로 지금 결정을 내리는 데 필요한 경로와 symbol을 먼저 찾고 필요한
범위만 부분적으로 읽는다. 각 경로에 이미 읽은 범위와 digest를 기록해 같은 결정을 위해
읽은 범위를 이유 없이 다시 읽지 않는다. 대용량 파일은 symbol 경계나 bounded offset으로
나누고 전체 로드는 명시된 교차 파일 불변식을 확인할 때만 허용한다.

구현은 의존성 순서의 작은 work unit으로 나누며 한 단위는 1~3개 파일만 소유한다.
각 단위가 끝날 때 테스트 결과와 변경 digest를 체크포인트로 남기고, 실패한 단위는 범위를
키우기 전에 원인을 분리한다. 장시간 작업은 체크포인트 사이에 새 요구를 끼워 넣지 않는다.

handoff에는 경로, 결정, 증거, 차단 요인, 다음 작업만 전달한다. 원문 전체, 반복 설명,
비밀값과 관련 없는 history는 전달하지 않는다. 이 정책은 토큰 잔량을 직접 관찰했다고
주장하지 않는다. 수치가 제공되지 않았는데 임의의 잔량이나 한계를 만들어내지 않는다.

`step_archive/step035_컨텍스트정책.md`에는 work unit 표, 읽기 ledger 형식, checkpoint
schema, 최소 handoff 예시와 차단 기준을 기록한다.

## 분리 검증

검증 패스는 파일 인덱스의 대표 신규·수정·대용량 행을 정책에 대입해 bounded 부분 읽기,
1~3개 파일 소유권, checkpoint와 handoff가 모호하지 않은지 확인한다.

## 완료 조건

- `context-policy`: 실행 가능한 bounded context 정책이 존재한다.
- `partial-inspection-policy`: 부분 읽기와 중복 읽기 방지 기준이 구체적이다.
- `small-work-units`: 각 작업 단위가 1~3개 파일이다.
- `minimal-handoff`: checkpoint와 handoff 필드가 최소화됐다.
- `no-token-balance-claim`: 관찰하지 못한 token balance를 주장하지 않는다.

정책과 검증 결과를 수락 증거로 제출하고 현재 단계에서 멈춘다. workflow 상태와
영수증만이 이후 진행을 소유한다.

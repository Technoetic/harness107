# Step 18 - API 계약 문서 조사

## 목표

주제와 프로젝트가 실제로 의존할 수 있는 API 계약 대상을 근거에서 도출하고, 공식
계약 문서의 요청·응답·오류·제약을 원본과 함께 조사한다. 주제와 무관하거나 근거
없는 API를 고르지 않는다.

## 입력과 산출물

- 입력: `step_archive/TOPIC/TOPIC.md`
- 입력: `step_archive/step016_조사결과_chunk1.md`
- 필수 선행 항목: `step016`
- 산출물: `step_archive/step018_조사결과_chunk1.md`
- 산출물: `step_archive/research-raw-step018-api-contract.txt`
- 네트워크: 필수
- 시각 검토: 필요하지 않다.

## 실행 역할

가능한 경우 계약 문서별 수집 역할과 계약 항목을 원본에 대조하는 독립 검토 역할을
나눈다. 수집 역할은 공식 문서와 버전 정보를 보존하고, 독립 검토 역할은 요약이
실제 계약을 넘어가지 않는지 확인한다. 역할을 나눠도 정상 권한 확인은 유지한다.
위임 기능을 사용할 수 없으면 현재 실행자가 수집과 독립 검토를 순서대로 수행하고,
별도 역할을 위임했다고 기록하지 않는다.

## 계약 대상 결정

주제 입력과 프로젝트 증거, 16단계의 실제 출처에서 다음 순서로 계약 대상을 도출한다.

1. 프로젝트 설정·소스에 이미 나타난 외부 API, 데이터 형식 또는 브라우저 표준
2. 주제의 상호작용을 구현하는 데 명시적으로 필요한 공개 계약
3. 공급자 공식 문서, 공개 명세 또는 버전이 고정된 표준 문서

대상 이름, 프로젝트 근거 경로, 사용 시나리오, 공식 계약 URL을 첫 청크에 적는다.
주제에 연결되는 구체적인 계약 출처를 식별할 수 없으면 `해당 없음`으로 통과시키지
말고 근거 부족과 사용자 조치를 기록한 뒤 이 단계를 완료하지 않는다.

## 문서 수집

지원되는 웹 또는 브라우저 수집 기능으로 공식 계약 URL을 실제 방문한다. 핵심 원문은
`step_archive/research-raw-step018-api-contract.txt`에 보존한다. 최대 다섯 개의 공식
출처만 조사하며 각 출처에서 다음 항목을 확인한다.

- 계약 버전과 기준 날짜
- endpoint 또는 메시지 형식, 필수·선택 필드와 자료형
- 인증, rate limit, 오류 및 재시도 계약
- 예제의 전제 조건과 호환성 제한

요청 URL, 최종 URL, 출처, 원본 경로, 응답 시각과 HTTP 결과를 함께 기록한다. 모든
사실 주장은 URL과 출처, 원본의 정확한 절 또는 캡처 위치로 추적되어야 한다. 문서에
없는 필드나 성공 조건을 추정하여 증거를 발명하지 않는다.

네트워크 기능을 사용할 수 없으면 원인을 기록한다. 공식 원본을 확보하지 못한
경우와 함께 정상 권한 확인 아래 최대 세 번만 재시도한다. 그래도 구체적인 계약과 원본을 검증하지 못하면 이 단계를
완료하지 않는다.

## 청크 계약

첫 결과는 `step_archive/step018_조사결과_chunk1.md`에 저장한다. 추가 청크는 각각
500줄 이하로 만들고 첫 청크 manifest에 경로, 줄 수, 계약 범위와 원본 위치를 적는다.

## 완료 조건

- `api-contract-chunk-1`: 계약 대상과 조사 결과가 있는 첫 청크가 존재한다.
- `api-contract-raw`: 공식 계약의 실제 원본 텍스트가 존재한다.
- `concrete-contract-subject`: 대상이 주제 입력과 프로젝트 근거에서 도출되었다.
- `api-contract-attribution`: 모든 계약 설명이 공식 URL과 원본 절로 추적된다.
- `api-contract-chunks-bounded`: manifest의 모든 청크가 존재하며 500줄 이하이다.

검증 결과를 수락 증거로 제출하고 이 단계에서 멈춘다.

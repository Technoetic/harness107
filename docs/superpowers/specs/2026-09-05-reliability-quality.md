# Harness50 reliability and measured quality

The 2.2 release repairs demonstrated failures in the published 2.1 adapters and adds reproducible output checks. It preserves the fifty-step workflow, receipt schema, read-only migration and normal Codex permissions. A numeric rating is a review judgment, not a guarantee of perfect generated products.

## Adapter safety

Claude auto-approval must be inactive for missing, malformed, paused or completed workflow state. Valid state must have a contiguous completed prefix and a current step consistent with that prefix. Canonical protected paths include parent traversal and versioned plugin cache locations. Preserve existing destructive-command denials; never execute regression payloads. Windows PowerShell 5.1 must parse and execute the exact installed script bytes. Project resolution is CLAUDE_PROJECT_DIR, then hook-event cwd, then process cwd; never an ancestor of the plugin cache. Stop-loop state is project scoped. POSIX stop_hook_active must be read before deciding whether to continue.

## Codex lifecycle

Worker-agent prompts cannot pause the parent workflow. Both qualified plugin skill names and existing short control names remain controls. Empty orphan lock directories left by interrupted creation, reclamation or release must become recoverable after a conservative stale interval, without stealing a live lock or following links. Existing receipt, fencing and race defenses remain intact.

## Measured output quality

Trust5 must no longer award points for coverage/src directory presence or treat scanner errors as success. Missing, malformed or failed evidence remains visibly incomplete or failed. Shared validation code produces machine-readable results with actual command exit status, bounded execution and artifact fingerprints. Hooks must not download tools or run arbitrary submitted evidence strings.

The final dist/index.html artifact must be a nonempty regular UTF-8 HTML document. An explicit local browser verifier loads it in Chromium at desktop and mobile sizes, records JavaScript errors, failed external requests, accessibility violations and screenshots, and writes a report bound to its SHA-256. Browser tooling is an explicit development dependency and is never installed by a hook. Browser verification is a reproducible product check, not proof of pedagogical or aesthetic quality.

## Release constraints

Node.js 22 and 24; Windows PowerShell 5.1; Linux and macOS Bash. No global configuration edits, model calls or automatic hook trust. Preserve original checkout and use improve/reliability-and-quality worktree branch. Test actual shipping files, expand OS coverage, run an independent review, publish only after remote checks pass. Document unverified live-model and user-study outcomes honestly.
